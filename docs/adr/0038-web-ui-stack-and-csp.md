# ADR 0038: The web UI stack, its dependencies and the content security policy

Status: proposed (card G3, pending PR review)

## Decision

- **Stack.** Svelte 5 with Vite and TypeScript in strict mode, no SvelteKit, in `web/`. The production build is static files in `web/dist` that the API serves on 5309. The Vite dev server is on 5150 and proxies `/api` with a rewritten `Host`, because the API only answers its own two loopback names. There is no server side rendering and one `index.html`: a hash router in `App.svelte` chooses the screen, so the API needs no extra routes.
- **Dependencies, and why each one.** One runtime dependency, `svelte`. Dev only: `vite` and `@sveltejs/vite-plugin-svelte` (build), `typescript` and `svelte-check` (strict types), `eslint`, `@eslint/js`, `typescript-eslint`, `eslint-plugin-svelte` and `globals` (lint, including the `{@html}` ban), `vitest`, `jsdom` and `@vitest/coverage-v8` (unit and component tests with the coverage gate), `@playwright/test` (browser tests, pinned to the version whose Chromium revision is preinstalled in the dev container), and `@types/node` (types for the test helpers and build scripts). Nothing else: no component library, no router, no state library, no CSS framework, no HTTP client (the typed client is about 100 lines on `fetch`). Every addition after this needs a reason here.
- **Licenses and audit.** The npm lockfile is checked by `scripts/check_licenses.py --npm-lock` against the same allow list as the Python dependencies, which gained the permissive `MIT-0`, `0BSD`, `BlueOak-1.0.0` and `CC0-1.0` for this. `npm audit --audit-level=high` runs in `audit.yml`. At the time of writing there are two low severity findings, both the same one: `deepmerge` (prototype poisoning in `mergeObject`, no fix available) reached through `@sveltejs/vite-plugin-svelte`. It is a build time tool merging configuration objects we write ourselves, nothing from it ships in the bundle, so the gate is `high` and the finding is recorded here. Revisit when a fixed release exists.
- **API types.** `web/src/lib/types.ts` is generated from the pydantic models by `scripts/gen_api_types.py` and a unit test fails when it is stale. The alternative of hand written types would drift silently.
- **Rendering.** Untrusted text is rendered only with Svelte text interpolation. `{@html}` is banned by ESLint (`svelte/no-at-html-tags`) and by `web/scripts/check-dist.mjs`, which parses every component for an `HtmlTag` node and checks the built bundle for inline scripts, inline handlers, `javascript:` URLs, `eval`, `new Function` and remote origins. Its tests build a scratch component with `{@html}` and show the check fail.
- **Content security policy.** The API sets one policy on every answer (G1 left the decision to this card): `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; font-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'; object-src 'none'`. No `unsafe-inline` or `unsafe-eval`. This works because Vite emits an external module script and an external stylesheet, and the UI sets no inline style or handler (it uses CSS classes). It is a header and not a `<meta>` tag so `frame-ancestors` works and a bundle change cannot drop it. A browser test checks the header and that the page loads with no policy violation and talks to its own origin only.
- **No automatic action.** The Analyze screen sends nothing until the button is pressed, a hosted backend needs an explicit tick, and no screen copies, sends or applies anything. A Playwright test checks that nothing is written before the button.
- **Tests.** vitest component tests run against a small real HTTP server that plays hand written API answers (the same pattern as the Python component tests). The Playwright tests run against the real API process, with a database seeded with stored reports (one full of hostile markup, hand written) and the backend pointed at a closed port, so they need no model. A separate `e2e:live` test needs a real Ollama and runs in `live.yml`.

## Why

A thin static front end keeps all rules in the library and API (one source of truth) and keeps the attack surface small: no framework server, no remote code, no inline script. A closed policy makes a missed escape much less harmful, because even an injected element cannot run script or call out.

## Limits

The policy cannot stop a bug in the API or a malicious browser extension. The generated types describe shape, not meaning. The Playwright suite proves rendering for the strings it plants, not for every possible string; the lint rule and the build check are what rule out the dangerous constructs. An IPv6 loopback address (`http://[::1]:5309`) is refused by the API's Host check, so the UI must be opened on `127.0.0.1` or `localhost`.
